# SAD · Кредитный конвейер

Кейс-чемпионат «ВПотоке», кейс №2 «Кредитный конвейер (скоринг и интеграции)».

**Работающая версия: https://credit.fashf.ru** · Команда SAD: Рахматуллин Динар, Чиранов Александр, Коломеец Софья.

Заявка на кредит автоматически проходит цепочку: **проверка анкеты → СМЭВ (госданные) → БКИ (кредитная история) → антифрод → ML-скоринг → решение**.
Если внешняя система упала или ответила подделкой, система не падает, а аккуратно отправляет заявку человеку на ручную проверку.

- ML: CatBoost на реальных кредитных историях российского БКИ (Альфа-Банк, 3 млн заявок); эмулятор БКИ отдаёт настоящие обезличенные истории, объяснение каждого решения через SHAP
- Антифрод: граф связей заявок по хэшам + эмбеддинги поведения ловят «кредитные фабрики» (только предупреждение, не отказ); самозапрет на кредиты
- Безопасность: JWT + 4 роли, HMAC-подписи обмена с СМЭВ/БКИ, хэширование и маскирование паспорта, журнал аудита с хэш-цепочкой
- Визуал: 3D-диорама конвейера (Blender), спидометр балла, «почему так решили», ползунки «а что если», 3D-граф антифрода, светлая и тёмная темы, версия для телефона


Архитектура и контракты: [docs/CONTRACTS.md](docs/CONTRACTS.md)

## Запуск

Три способа, от самого простого. Адрес: **http://localhost:5173** (Docker — **http://localhost:8080**).

**1. Одной командой (мак, без Docker)** — нужны `uv` и `npm`:
```bash
scripts/run.sh
```
Скрипт сам ставит зависимости, поднимает СМЭВ (8101), БКИ (8102), backend (8000) и фронт (5173), ждёт готовности и печатает адреса.
Порты меняются переменными `SMEV_PORT`, `BKI_PORT`, `BACKEND_PORT`, `FRONT_PORT`. Логи — в `logs/`. Остановка — Ctrl+C (или `scripts/stop.sh`).

**2. Страховка на защите — только фронт на заглушках** (backend и модель не нужны):
```bash
scripts/run.sh --mock
```

**3. Docker:**
```bash
docker compose up --build
```
Наружу открыт только фронт на 8080 (меняется `FRONT_PORT=...`). Фронт раздаёт nginx и проксирует `/api` в backend (SSE работает). Хаос-панель из UI работает: эмуляторы пускают `/chaos` из сети compose.

### Вход в систему

Публичных паролей нет. При первом запуске backend сам создаёт 4 учётки (оператор, риск-менеджер, аудитор, администратор)
со случайными логинами вида `op.7f3a9c` и длинными паролями и пишет их в **`secrets/credentials.local.md`** (таблица)
и `secrets/credentials.local.json`. Папка `secrets/` в `.gitignore`, файлы с правами 600. В БД лежат только bcrypt-хэши.
Свой файл можно положить заранее (формат — список `{username, role, password}`), путь меняется переменной `CREDENTIALS_FILE`.
В Docker файл лежит в томе с базой: `docker compose exec backend cat /data/credentials.local.md`.
Регистрации нет: учётки сотрудникам выдаёт администратор.

| Роль | Что может |
|---|---|
| оператор (`operator`) | создавать заявки, what-if |
| риск-менеджер (`risk_manager`) | ручные решения по спорным заявкам |
| аудитор (`auditor`) | журнал аудита и проверка цепочки |
| администратор (`admin`) | мониторинг, стенд испытаний (хаос-режимы, атаки), журнал |

### Магические паспорта для демо

| Паспорт | Что произойдёт |
|---|---|
| `0000 000001` | идеальный клиент → одобрение |
| `0000 000002` | плохая кредитная история (высокий риск, текущая просрочка) |
| `0000 000003` | СМЭВ: паспорт недействителен |
| `0000 000004` | БКИ: кредитной истории нет → ручная проверка |
| `0000 000005` | пограничный клиент → ручная проверка |
| `0000 000006` | самозапрет на кредиты → отказ |

Остальные паспорта дают детерминированного «случайного» человека (одна и та же история на один и тот же паспорт).

### Настройки

Все параметры задаются переменными окружения; для локального демо ничего задавать не нужно — у каждой есть безопасное для разработки значение по умолчанию. В боевом режиме (`APP_ENV=production`) сервер не запустится с секретами по умолчанию.

| Переменная | Зачем |
|---|---|
| `APP_ENV` | `production` — боевой режим: запрет секретов по умолчанию, закрытая документация API |
| `JWT_SECRET` | подпись токенов входа (сгенерировать: `openssl rand -hex 32`) |
| `SMEV_HMAC_SECRET`, `BKI_HMAC_SECRET` | общие секреты HMAC-подписи обмена с СМЭВ и БКИ |
| `PII_PEPPER` | «перец» для хэша паспорта; потеряете — старые хэши не восстановить |
| `SMEV_URL`, `BKI_URL` | адреса эмуляторов |
| `DATABASE_PATH` | файл SQLite |
| `CREDENTIALS_FILE` | где лежат учётки сотрудников (по умолчанию `secrets/credentials.local.json`) |
| `ADMIN_PASSWORD` | необязательно: свой пароль администратора (от 12 символов) |
| `EMPLOYER_CHECK` | `offline` (контрольная сумма ИНН) или `fns` (ЕГРЮЛ ФНС с откатом на offline) |
| `DUPLICATE_CHECK` | `off` выключает правило «одна заявка на паспорт» (только для демо) |
| `CORS_ORIGINS` | разрешённые источники через запятую |

## Структура репозитория

```
common/        HMAC-подпись обмена с внешними системами
emulators/     эмуляторы СМЭВ и БКИ (реальные обезличенные истории Альфа-Банка)
ml/            обучение, инференс, SHAP; артефакты модели в ml/artifacts/
backend/       FastAPI: конвейер, безопасность (JWT, роли, аудит), SQLite
frontend/      Vite + Svelte 5 + TypeScript + ECharts + Threlte (3D-сцены в frontend/public/3d/)
scripts/       run.sh / stop.sh / run_test_cases.py
docs/          архитектура и контракты, безопасность, словарь данных, журнал ИИ
```
