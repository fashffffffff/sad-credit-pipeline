# SAD! · Кредитный конвейер

Кейс-чемпионат «ВПотоке», кейс №2 «Кредитный конвейер: от заявки до решения».

**Работающая версия: https://credit.fashf.ru** · Команда SAD!: Рахматуллин Динар, Чиранов Александр, Коломеец Софья.

Клиент банка сам подаёт заявку на кредит с телефона или компьютера и за секунды получает **предварительное решение с понятной причиной**:
одобрено, отказ (и «вот так одобрим», если отказ можно исправить суммой или сроком), «нужны данные» или ручная проверка.

- **Решение — по правилам кейса:** балл 0–100 по 5 признакам, DTI по аннуитету, лимиты, 12 правил строго по порядку, коды причин из каталога. Одно ядро `credit_core/` для консольного прототипа и для сервиса. На `applications.csv` 91 решение из 100 совпадает с разметкой, остальные 9 объясняются построчно.
- **Паспорт не покидает устройство клиента:** браузер «маскирует» номер по протоколу OPRF (RFC 9497), токенизатор применяет свой ключ, не видя номера. В заявку уходит только отпечаток `passport_hash`.
- **Внешние системы — отдельные сервисы на Go:** эмуляторы БКИ и СМЭВ по спецификации кейса (детерминированы, с режимами сбоев) и токенизатор паспорта. Обмен подписан HMAC, таймаут 3 с × 2 попытки, таймаут — не отказ.
- **Бэк-офис:** андеррайтер разбирает ручные проверки (с подсказкой ML-модели CatBoost на реальных историях Альфа-Банка — на решение она не влияет), аудитор читает журнал с хэш-цепочкой, режим зала с QR для живого демо.

Архитектура и контракты: [docs/CONTRACTS.md](docs/CONTRACTS.md)

## Консольный прототип (только стандартная библиотека Python)

```bash
python prototype/04_прототип.py data/case2/applications.csv --out decisions.csv
python prototype/04_прототип.py data/case2/applications.csv --explain app_0005
```

Пишет `decisions.csv` (app_id, decision, reason, score, dti, amount_approved, term_approved), печатает сводку и объясняет каждое расхождение с разметкой CSV.
`--emulate` — ответы БКИ и СМЭВ по формулам эмуляторов вместо колонок CSV.

## Запуск всей системы

Нужны `uv`, `go` и `npm`. Адрес: **http://localhost:5173**.

```bash
AUTH_DEMO=1 bash scripts/run.sh
```

Скрипт ставит зависимости, собирает Go-сервисы в `bin/`, поднимает СМЭВ (8101), БКИ (8102), токенизатор (8103), backend (8000) и фронт (5173). Остановка — Ctrl+C или `bash scripts/stop.sh`. Логи — в `logs/`, журнал вызовов внешних систем — `logs/external.log`.

Только фронт на заглушках (страховка на защите): `bash scripts/run.sh --mock`. Docker: `docker compose up --build` (наружу — фронт на 8080).

### Вход

- **Клиент** — по номеру телефона, без пароля: Яндекс ID, звонок (SMS.RU callcheck), Telegram-бот или VK ID — включаются ключами в `.env` (как получить — [docs/REGISTRATION_GUIDE.md](docs/REGISTRATION_GUIDE.md)). Без ключей или с `AUTH_DEMO=1` — демо-код прямо на экране.
- **Сотрудники** (`/staff`) — андеррайтер, аудитор и администратор стенда. Учётки со случайными логинами и паролями backend создаёт при первом запуске в `secrets/credentials.local.md` (папка в `.gitignore`, права 600).

| Роль | Что может |
|---|---|
| клиент | подать заявку, видеть только свои заявки, принять встречное предложение, скачать справку |
| андеррайтер | очередь ручной проверки, ручное решение, пересчёт, пакетный прогон CSV |
| аудитор | журнал аудита и проверка цепочки, журнал внешних вызовов (только чтение) |
| администратор стенда | хаос-режимы БКИ/СМЭВ, симулятор атак, режим зала (только для демо) |

### Настройки

Для локального демо задавать ничего не нужно. При `APP_ENV=production` сервисы не запустятся с демо- или короткими секретами. Полный список — [.env.example](.env.example).

| Переменная | Зачем |
|---|---|
| `APP_ENV` | `production` — боевой режим |
| `JWT_SECRET`, `PII_PEPPER` | подпись токенов; «перец» для отпечатка телефона |
| `SMEV_HMAC_SECRET`, `BKI_HMAC_SECRET`, `TOKENIZER_HMAC_SECRET` | общие секреты подписи обмена с Go-сервисами |
| `OPRF_PRIVATE_KEY` / `secrets/oprf.key` | ключ токенизатора паспорта (создаётся сам) |
| `CERT_SIGNING_KEY` / `secrets/cert_ed25519.key` | ключ подписи справок (создаётся сам) |
| `PUBLIC_BASE_URL` | адрес сайта для QR справки и OAuth |
| `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `SMSRU_API_ID`, `TELEGRAM_BOT_TOKEN`, `VK_CLIENT_ID` | способы входа клиента |
| `AUTH_DEMO`, `AUTH_IP_LIMIT_PER_HOUR` | демо-код; лимит входов с одного IP (по умолчанию 60) |
| `DUPLICATE_CHECK` | `off` выключает «одна активная заявка на паспорт» (только для тестов) |

## Структура репозитория

```
credit_core/   правила кейса: баллы, DTI, 12 правил, продукты, встречные предложения, каталог причин
prototype/     консольный прототип 04_прототип.py
data/case2/    данные организаторов: applications.csv, products.csv
services/      Go: эмуляторы СМЭВ и БКИ, токенизатор паспорта (OPRF)
backend/       FastAPI: конвейер, API /api/v1, вход клиента, роли, аудит, справка PDF, антифрод
ml/            модель-подсказка (CatBoost + SHAP на историях Альфа-Банка)
frontend/      Svelte 5: приложение клиента и бэк-офис, 3D-сцены
scripts/       run.sh / stop.sh / run_test_cases.py
docs/          контракты, безопасность, словарь данных, журнал ИИ
```
